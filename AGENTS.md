# Notes for coding agents

This repo parses financial documents: classify with the Decisions API, extract with Claude or GPT into a Zod schema, check the numbers in plain code, verify doubtful fields, score.

## Commands

- `npm test`: unit and pipeline tests with fake model clients. No keys needed. Run after every change.
- `npm run typecheck`
- `npm run eval`: real models against `samples/`. Needs `OPENAI_API_KEY`. Run before and after any prompt, schema or model change and compare the four numbers.
- `npm run samples`: regenerate the made-up sample PDFs and labels.
- `npm run parse -- <file>` and `npm run dev`

## Rules

- **Never default a document type.** If the classifier is unsure, the result is `needs_review`. Don't add a fallback type.
- **Checks are plain code.** Never ask a model whether numbers add up. A check returns `skip`, not `pass`, when an input is missing.
- **Schemas are nullable.** Every leaf can be null so the model never has to invent a value. Use enums for categories.
- **Field descriptions are instructions.** The model reads them. Fix a recurring extraction mistake in the description or the variant's rules before touching the shared prompt.
- **A quote is not proof.** Finding the source text in the document can only lower a score, never raise it.
- **Ask the Decisions API many questions in one request** rather than many requests. Questions run in parallel.
- **Keep real customer documents out of the repo.** Samples are generated by `scripts/generate-samples.ts`.

## Adding a document type

1. Make `src/documents/<type>/` with `schema.ts`, `checks.ts` and `index.ts`, following `pay-stub/`.
2. Add it to `src/documents/index.ts`.
3. Add a sample layout in `scripts/samples/` and a few documents in `scripts/generate-samples.ts`, with numbers that tie out.
4. Add check tests in `test/checks.test.ts`: one passing sample, and one test per mistake the checks should catch.
5. Run `npm test`, then `npm run eval`.
